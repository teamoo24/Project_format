# Project_format

新しいゲームを始める前に、エージェントへ渡す型。  
Ariadne でうまくいった **ナビつき** を、次の作でも使えるようにしたもの。

エージェントの強みは型を埋めることと、進みを3ファイルに残すこと。  
本人の強みはエディタを触ること。**ゲーム本体は代筆しない。**

## 3ファイルの役割

レッスンが始まったあとのゲームレポでは、この3つが本体になる。

| ファイル | だれ向け | 役割 |
|---|---|---|
| `AGENTS.md` | エージェント | ナビのルールと「この作だけ」 |
| `PLAN.md` | 両方 | 全体地図。「その次」は小さい課題の列 |
| `README.md` | 本人 | 今日のメモ。「クリア」「いまのレッスン」 |

型の中身:

- [SKILL.md](SKILL.md) … ナビのルール（エージェントが先に読む）
- [agents-template.md](agents-template.md)
- [plan-template.md](plan-template.md)
- [readme-template.md](readme-template.md)

## エージェントへの頼み方

このレポを開いて（または `SKILL.md` を渡して）:

```
新しいゲームを始めたい。ナビつきで型を埋めて。
```

アイデアだけあるときは、その一文を足す。足りない穴はエージェントが聞く。  
埋まってから、ゲームレポへ `AGENTS.md` / `PLAN.md` / `README.md` を出す。

レッスン開始後はゲームレポで「次のレッスン」「できた」。

## アイデアから型（エージェント向け）

ゲーム本体はまだ作らない。会話で穴を埋め、3ファイルを書く。

### 1. 核だけ聞く

一度に全部聞かない。先にこれだけ。

- だれが作るか
- エンジン（Godot など）
- 一言で何のゲームか（本人の言葉）
- 形の参考（講座・見本のリンク）。**参考を作り直さない**
- 参考と同じところ / 今作だけにあるところ

核が曖昧なら、企画を少しだけ整理してから型に入る。設計書にはしない。

### 2. 足りない穴だけ聞く

- ゲーム名、レポ名
- 今のメインシーン、手本の脚本、コメントの言語
- 困ったときの章リンク（タイムスタンプ付き。最初から再生させない）
- 後回し（タイトル、セーブ、ギャラリーなど）
- 触らない試作フォルダ（無ければ無し）
- 本人の既知（たとえ用。例: ツリー ≒ DOM）
- 売り方の目安（例: 500円なら核だけで足りる）。無ければ書かない
- ここまでできたこと。無ければ「まだレッスン前」

本人が言っていない穴は、勝手に埋めない。聞いてから書く。

### 3. 型をコピーして `{{}}` を全部埋める

ゲームレポのルートへ:

1. `agents-template.md` → `AGENTS.md`
2. `plan-template.md` → `PLAN.md`
3. `readme-template.md` → `README.md`

`{{}}` は残さない。不要な節（触らない試作など）はテンプレの指示どおり削除する。  
3ファイルでレッスン名・クリア・企画の言い方を揃える。

### 4. 最初のレッスンは1本だけ

- `PLAN.md` の「その次」は、実行して分かる変化が1つの列。参考の大きい章を1レッスンにしない
- `README.md` の「いまのレッスン」は先頭の1本だけ。次の中身は出さない
- 「クリア」は、ここまでできたこと。レッスン前なら短くそう書く

本人が「これで」と言うまで、シーン・UI・脚本は作らない。

### 5. 渡し方

ゲームレポがもうある → そこに3ファイルを置く。  
まだ無い → この会話で3ファイルの中身を出し、本人がレポを用意してから置く。  
このフォーマットレポのテンプレは上書きしない。

## レッスンが始まったら

進め方は [SKILL.md](SKILL.md)。ゲームレポの `AGENTS.md` があるときはそちらを優先する。

1回にレッスン1本。クリア（「できた」）が来たら、短く認めて次の1本だけ出す。

## しないこと

- 企画の会話のうちに、ゲームを完成形として代筆しない
- 参考作を丸コピーして今のシーンを捨てない
- レッスンを並べて「全部やれ」にしない
- 設計書だけで終わらせない。返答はゲームの課題として書く
- タイトル・セーブ・ギャラリーなど後回しを、核より先に足さない
